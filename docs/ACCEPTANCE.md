# 刷写前的验收状态

当前不具备正式安装条件。主机测试、临时启动和持久安装是三个不同阶段。
“编译通过”“生成文件”不能标为手机功能通过。任何尚未实测的功能都保持待验证。

## 已完成的主机检查

| 项目 | 结果 | 限制 |
| --- | --- | --- |
| 存储读取并发与日志缓冲区隔离 | 回归测试通过，旧实现可被检测出来 | 未验证真实DMA/cache/UEFI时序 |
| 安装头缓冲区 | 修复128字节对象接收4096字节数据的问题，内存检测通过 | 尚未在固件执行 |
| 分区读取边界 | 空指针、异常介质、整数溢出、跨块与尾块用例通过 | 使用模拟Block I/O |
| 镜像布局与输出 | APFS结构/内核架构/载荷大小/数据区重叠检查，失败保留原输出 | 不是完整APFS fsck；仍为作者的固定布局 |
| 镜像完整性 | SHA-256已接入加载器；标准/二进制向量、分块输入和篡改用例通过 | 不是签名认证；固件执行耗时未测 |
| 保存槽选择 | 校验内容后才决定保留哪一槽；损坏槽和恢复回退用例通过 | 模拟解包，不等于文件系统完整保存/恢复 |
| EFI与保存程序交叉编译 | 曾通过；每次修改后需重新编译 | 未进行真机启动 |
| 完整内核构建 | 已生成链接内核；完整make尚有导出符号集问题 | 不得标为全部构建检查通过 |

`scripts/build-image.py`默认设置`ufs_write=0 var_store=0`、120秒会话。
启用持久化需显式给出CMDLINE，并先满足下面的安装条件。脚本只生成本地文件。

当前基础素材组合曾被检查出超过固定保存区起点8,177,904字节；构建器已经拒绝该组合。
应重新压缩/裁剪镜像或统一重新设计loader、kernel、var_store的布局，不能只改一个数字。

## 临时启动前必须完成

- 当前安卓引导及设备独有分区的可用备份：boot两个槽、dtbo、vbmeta、vendor_boot、
  persist、modemst1/modemst2、fsg/fsc等，以本机实际分区表为准。
- 验证能用匹配的恢复环境返回当前安卓；下载中的恢复包不算验证完成。
- 从本机取得DTB和所需GPU/WiFi等固件；核实内存窗口和UEFI来自适配的thyme构建。
- 解决完整构建检查与布局冲突；核对每个产物的提交、构建参数和SHA-256。
- 准备有时限、可取日志的RAM启动包，先关闭持久写入；为本机核对每个实际写入路径，
  包括加载器诊断日志。不能仅凭`ufs_write=0`声称完全不写闪存。

## 真机核心功能验收

以下全部仍为待验证。需要用准确的镜像哈希和日志记录结果。

| 功能 | 通过标准 |
| --- | --- |
| 启动与退出 | 多次进入桌面；超时/正常结束可返回loader或安卓；故障时可取日志 |
| 触摸与显示 | 点击、滑动、边缘手势、多点触控、旋转/锁屏恢复；记录幻触和实际帧率 |
| GPU | 日志确认硬件渲染；连续操作无挂死；退出后可重新启动，检查冷重启需求 |
| 实体按键 | 电源、音量、锁屏、唤醒连续使用正常 |
| WiFi | 不止扫描：关联、DHCP、DNS、HTTPS访问、断线重连、休眠恢复 |
| 电源与充电 | 真实电量与温度；连接充电后电量/电荷上升；拔线切换及长时间运行正常 |
| 持久化 | 设置和测试文件至少三轮保存/重启/恢复一致；损坏新槽能回退；不能半恢复后直接启动桌面 |
| 音频 | 扬声器播放、音量变化、麦克风录制与回放、锁屏/唤醒后工作 |

相机、蓝牙、通话/SMS/移动数据和第三方应用安装另外逐项验证，目前不能承诺可用。
如果这些是使用目标的一部分，它们也必须通过后才算满足目标。
不能把其他机型成功、仓库宣称支持或安卓下的正常行为算作本机移植的通过结果。

## 持久安装条件

只有恢复保障、本机布局、必要功能及数据恢复完成真机验收，才准备持久安装包。
当前安卓位于B槽，不能套用作者“安卓A/iOS B”的示例覆盖boot_b。
接受清空数据不代表可以省略设备独有分区备份和恢复验证。
