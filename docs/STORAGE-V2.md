# 存储格式v2：实现中，尚不可安装

v1使用固定保存区起点，旧素材快照越界8,177,904字节；本轮文件大小规划为8,177,952字节。
v2将保存区描述放入
安装头中，按实际镜像长度对齐计算起点，再按显式分区容量校验两个槽。
格式、构建器和运行时布局传递已接入主机测试；未完成本机验收，不能据此刷机。

## 字节布局

所有整数为小端。头大小4096字节；payload紧接头，system紧接payload。

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 8 | `IOSSTOR2` |
| 8 | 4 | version=2 |
| 12 | 4 | boot_mode |
| 16..63 | 48 | 与v1相同的payload/system/region长度及flags；仅连续region A，flags=0 |
| 64 | 8 | store_at：相对本分区的字节偏移 |
| 72 | 8 | slot_bytes |
| 80 | 4 | slots=2 |
| 84 | 4 | block_bytes=4096 |
| 88 | 8 | layout flags=0 |
| 96 | 32 | SHA-256(header[0:96] + payload + system) |
| 128 | 3968 | 零填充，不放置额外语义 |

描述符C ABI为`thyme_store_layout`，大小32字节。`thyme_store_layout_valid`和
Python `valid_v2_layout`保持同样的范围规则，并用边界/随机输入交叉验证。
镜像末端必须不大于store_at；起点和槽大小按4096对齐；槽至少8192字节；
两个槽必须完整处于显式容量内；整个布局必须可用有符号64位文件偏移表示。
先减后除校验剩余容量，避免乘法溢出。

v2完整性校验覆盖描述符及头部；这是损坏检测，不是发布者签名认证。
v1仍按原payload+system摘要处理，不能以修改版本字段冒充v2。

## 当前构建入口

默认仍生成v1并拒绝旧保存区重叠。仅为本地格式实验时，可以显式设置
`LAYOUT_VERSION=2 PARTITION_BYTES=<候选分区字节容量>`运行构建器。
这里的容量必须来自实际安装方案，不能将示例4GiB当作本机GPT实测值。
输出文件只包含头、payload和system，保存区槽不写入输出；所需完整容量另行校验。
构建结果包含`integration_status`，目前明确标记本机验收与迁移尚未完成。
[本轮大小规划](reports/storage-v2-plan.json)只读取现有素材大小并计算布局，未生成完整安装包；
其4GiB容量是测试假设，所列store_at=2,511,654,912字节不是本机安装授权。

## 已接入的运行时链路及限制

1. Loader校验v2头与完整摘要后，才把布局绑定到本次启动及对应的实际分区。
2. 通过版本化mailbox向内核传递描述符、分区关联和镜像末端；混用旧协议必须拒绝。
3. Loader和内核只允许写入该布局两个槽的范围，仍保持默认关闭写入及分区身份限制。
4. 保存程序从内核获取经过校验的布局；不允许在布局未知时回退到旧偏移猜测。
5. 覆盖协议不匹配、布局篡改、跨槽边界、重复会话、恢复/保存以及旧格式行为。

mailbox版本为4，布局信息使用原ask之前的padding，ask偏移仍为128。
`thyme_store_info`包含版本、保留位、镜像末端、分区容量及32字节描述符，总长56。
只读`kern.redwood.var_layout`发布经过关联校验的副本；保存程序拒绝查询失败、长度不符、
未知版本和非法范围，不能猜测旧偏移。重复或未创建的darwin设备节点不提供布局。
启动绑定只消费一次；普通RAM载荷没有经过安装头及摘要验证时不提供保存权限。

需要匹配构建的loader、kernel、init和var_store；旧mailbox v3拒绝，不自动降级。
默认loader仍关闭直接写盘，构建器仍使用`ufs_write=0 var_store=0`。
专用可写构建还必须通过现有位置、大小、逻辑单元和GUID检查；这些仍是作者布局约束，
没有因为v2格式而被改成本机实测值。

主机测试已覆盖C/Python生成镜像的头和摘要、协议/ABI、节点与分区关联、一次性绑定、
保存程序协商、真实临时文件归档及EFI模拟块服务。块服务以真实EFI介质参数做边界校验，
不相信共享表中可变的块大小/容量；flush失败或读回不符均不能报告成功。
这些检查不能代替DMA/cache时序、真实固件、掉电持久性和手机多轮恢复测试。

不支持原地自动升级。v2镜像可能占用旧v1保存区，不能直接覆盖已有安装。
必须先备份旧数据，并采用空白专用分区或经过单独验证的迁移流程；本仓库尚未提供该流程。
